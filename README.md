# live-testdata

Binary WSS captures and manifests for cross-lib replay tests.

## Usage

Clone next to your lib repo:

```bash
git clone https://github.com/PirateTok/live-testdata ../live-testdata
```

All PirateTok libs look for `../live-testdata/captures/` by default. You can also set `PIRATETOK_TESTDATA` to point to this directory.

## Structure

```
captures/
  calvinterest6.bin              # raw WSS frames (LE u32 length-prefixed)
  happyhappygaltv.bin
  fox4newsdallasfortworth.bin
  manifests/
    calvinterest6.json           # ground truth generated by Rust golden standard
    happyhappygaltv.json
    fox4newsdallasfortworth.json
```

## Capture format

Each `.bin` file is a sequence of length-prefixed protobuf frames:

```
[u32 LE length][frame bytes][u32 LE length][frame bytes]...
```

Frames are raw `WebcastPushFrame` protobuf messages as received over WSS.

## Manifest format

Each `.json` manifest contains deterministic counts and sequences:

- `frame_count`, `message_count`, `event_count`
- `decode_failures`, `decompress_failures`
- `payload_types`, `message_types`, `event_types` (count maps)
- `sub_routed` (follow, share, join, live_ended counts)
- `unknown_types` (unrecognized message types)
- `like_accumulator` (event-by-event LikeAccumulator validation)
- `gift_streaks` (group-by-group GiftStreakTracker validation)

Manifests are generated by the Rust lib (`cargo run --bin generate_manifest`). All other libs must reproduce these exact values.
